Module 3: Feature Engineering

This module explores the transformation of raw data into features for machine learning. It covers multivariate regression with matrix notation, followed by key feature engineering techniques such as scaling, encoding, and selection.

Learning Objectives

  • Define multivariate linear regression using matrix notation and compute predictions.
  • Describe common feature engineering tasks (handling missing data and scaling features).
  • Apply transformations such as log scaling, z-score normalization, and bucketing.
  • Encode categorical variables and construct feature crosses.
  • Evaluate features for inclusion in a model using selection strategies and discuss the curse of dimensionality.

The through-line

Models see only the numbers you hand them. This module is about the gap between raw data and those numbers — the unglamorous work that decides more real-world projects than the choice of algorithm does.

It opens by generalizing regression to many inputs, in matrix form: X becomes a table, w a vector, prediction a product. That notation is not just compact — it is how every library expects your data, so learn to read shapes: rows are examples, columns are features.

Then the craft. Features on wildly different scales (income in dollars, age in years) tilt the loss surface so gradient descent zigzags; standardization levels it. Missing values must become numbers somehow — dropped, imputed, or flagged — and each choice encodes an assumption you should be able to defend. Categorical values become one-hot vectors, because handing "red=1, green=2, blue=3" to a linear model invents an ordering that does not exist.

The last two parts add expressive power without leaving the linear world. A feature cross multiplies two features so the model can respond to their combination — location and size, not location plus size. Bucketing turns a continuous value into ranges, letting a straight-line model fit a curve in steps.

The habit to build this week: when a model underperforms, look at the features before reaching for a fancier algorithm. Most of the fix is usually here.

Figure · Features make it linear

The data is curved; the model is linear and stays linear. The only thing you control is which columns it sees. Toggle features and watch the same least-squares solver succeed or fail.

With x alone the best line misses the shape entirely. Add the x² column and the fit snaps in — no new algorithm, just a better table handed to the same solver. That is feature engineering: the model is only as expressive as the columns you build. (|x| gets partway there; sin 3x is a wrong guess and the solver correctly gives it little weight.)

Key concepts

  • Multivariate Regression: Multiple input features
  • Feature Scaling: Normalization, standardization
  • Encoding: Converting categorical variables to numbers
  • Feature Crosses: Combining features to capture interactions
  • Curse of Dimensionality: Problems with high-dimensional data
