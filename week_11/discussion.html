Module 11: Discussion Topics

Higher-Order Thinking for Class Engagement

These discussion prompts move beyond the mechanics of the Functional API toward what an architecture claims — about the data, about the task, and about the people in the rows.

Epistemology / Analysis

1. Architecture as Hypothesis

Bucketing age asserts that age’s effect is not smooth. An embedding asserts that categories have geometry worth learning. Every wire in the diagram encodes a belief about the world.

  • What belief does giving fare its own normalized path encode? What would make it false?
  • What would the data have to look like for raw age to beat bucketed age?
  • Is a model diagram a scientific claim? Could you design an experiment to falsify one wiring against another?
  • The lecture chose bucket boundaries 12 / 25 / 40 / 60 by hand. What is that, if not a prior?

Try: have students propose one wiring change each and state the belief it encodes before running it.

Engineering / Evaluation

2. The Parameter Bill

The figure on the module page prices every wiring choice in parameters. Treat the count as a budget and the architecture as spending.

  • An embedding for a 3-category column costs 16 parameters here. What breaks first as the vocabulary grows to 30,000 — one-hot’s width or the embedding’s parameters?
  • The trunk dominates the bill at (width + 1) × 16. When does narrowing the concat matter more than shrinking any encoder?
  • Is a lower parameter count ever worth a worse dev accuracy? Who decides?
  • Hand-compute the bill for one model, then verify with the trainable-weights sum. Where does count_params() mislead, and why?

Try: give teams the same dev-accuracy target and rank their models by parameter count.

Synthesis / Design

3. The Second Head

The two-headed model predicts survival and fare bracket from one trunk — and fare had to leave the inputs to become a target.

  • When does an auxiliary head help the main task, and when do the two objectives fight over the trunk?
  • The loss weights were 1.0 and 0.5. What is that ratio a statement about? Who should set it?
  • Predicting a value you also feed in is leakage. Find one subtler leakage risk in this module’s pipeline.
  • Propose a third head for this dataset that would plausibly help survival prediction — and one that would plausibly hurt it.

Try: train the survival-only model against the two-headed one and discuss the gap, whichever direction it goes.

Ethics / Critical Analysis

4. A Manifest of People

The rows are passengers who lived or died in 1912, and the strongest single feature is sex. The convenience of the dataset is exactly what deserves examination.

  • The one-rule baseline (“females survived”) is strong because of a social protocol. What does the model learn, physics or policy?
  • Would you ship a model whose top feature is a protected attribute? What if removing it tanks accuracy?
  • What does cabin class stand in for? Is pclass a feature or a proxy?
  • This is the doorstep of module 12. Which fairness questions can already be asked of the two-headed model, with the tools you have?

Try: compute survival-head accuracy per sex and per class before module 12 names the metrics.
